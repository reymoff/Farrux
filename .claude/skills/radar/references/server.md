# База на сервере, слежение, шаги после разбора

## Постоянная база и слежение (сервер)

База радара живёт в Supabase и не теряется между сессиями. Работать через инструменты коннектора ai-targetolog (`mcp__ai-targetolog__radar_*`); если их нет в сессии, загрузить через ToolSearch. Локальная база `radar.py` нужна только для просмотра роликов и выгрузки файлов.

| Инструмент | Что делает |
|---|---|
| `radar_sync {usernames[], pages, niche, geo, lang, kind, watch}` | собирает до 10 аккаунтов за вызов и сохраняет: профиль, публикации, медианы, выбросы, снимок дня. Возвращает сводку и топ-8 по каждому |
| `radar_list {niche, geo, lang, gender, age, kind, watch, min_followers}` | аккаунты из базы с фильтрами |
| `radar_top {usernames, niche, geo, lang, type, min_outlier, days, only_unanalyzed}` | публикации по всей выборке, по выбросу |
| `radar_tag {username, ...}` | метки и флаг слежения |
| `radar_note {code, hook, hook_type, analysis, transcript, text_on_screen, lang, duration, cuts}` | сохранить разбор ролика. Вызывать после каждого разбора |
| `radar_hooks {niche, lang, hook_type}` | библиотека хуков из разобранных роликов |
| `radar_history {username | code}` | динамика подписчиков и просмотров по дням |
| `radar_watch_now` | обойти аккаунты на слежении и отправить залетевшее в Telegram |
| `ig_radar {username, video_for, images_for}` | свежие ссылки на видео и картинки (живут несколько часов, в базе не хранятся) |

Слежение: аккаунты с `watch: true` обходятся каждый день в 08:17 по Ташкенту. Новые публикации с выбросом от x3 за последние 14 дней уходят директору в Telegram. Ставить на слежение, когда владелец говорит "следи", "отслеживай", "мониторь".

Порядок любой задачи: сначала `radar_list` или `radar_top` (вдруг аккаунт уже в базе и свежий), потом `radar_sync` для новых или устаревших. Перед выгрузкой файлов: ответы `radar_list {full: true}` и `radar_top {min_outlier: 0, limit: 500}` сохранить в json и прогнать через `radar.py ingest`, затем `export`.

Ссылки на видео недолговечны, поэтому после просмотра ролика сразу сохранять суть через `radar_note`: к тексту разбора можно вернуться всегда, к самому видео нет.

## После разбора: что ещё делать

- **Сценарии.** После вердикта по залетевшему ролику предложить 3 сценария под нишу владельца через скиллы `reels-scenarist` и `copywriter`. Адаптировать приём, а не копировать ролик.
- **Реклама конкурента.** Библиотека рекламы Meta: инструмент `mcp__Meta_ads__ads_library_search` по названию страницы. Какие креативы крутят, как давно, сколько вариантов. Долго живущее объявление это рабочее объявление.
- **Комментарии.** Официальный API не отдаёт текст комментариев под чужими публикациями. Есть `vidiq_instagram_comment_list` (кредиты, с согласия владельца). По комментариям искать вопросы, возражения и споры: это темы для роликов.
- **Сравнение с владельцем.** Его аккаунт и клиентские (список через `meta_read` path `me/accounts`, fields `name,instagram_business_account{id,username}`) доступны с полной статистикой: `<ig_id>/media` с `insights.metric(reach,views,saved,shares,total_interactions)`. Сравнивать с конкурентами по медиане просмотров, ER, частоте, доле форматов, типам хуков. У своих писать ещё сохранения, репосты и охват.
